## Что это

Trinotify перехватывает **все** уведомления и входящие звонки и по каждому
событию принимает решение: пропустить со звуком, показать беззвучно или
заблокировать полностью.

Одни приложения будят вас звуком, другие молчат, третьи вообще не показываются —
и всё это настраивается по приложению, по отправителю или отдаётся на откуп
локальному классификатору, который учится на вашей собственной разметке.

Всё работает **офлайн**: приложение не делает ни одного сетевого запроса.

## Возможности

### Уведомления

- **Перехват всех уведомлений** в реальном времени.
- **Правила по приложению**: со звуком · тихо · блокировать · решает ML.
- **Правила по отправителю** — по подстроке в заголовке или тексте, с
  необязательной привязкой к конкретному приложению.
- **Блокировка несмахиваемых уведомлений** — включая постоянные «демоны»
  сторонних приложений, которые обычно нельзя убрать.
- **Зачистка уже висящих уведомлений** сразу после изменения правила.
- **Умное подавление повторов**: обновления прогресса и служебные перепосты не
  звучат по второму разу.
- **Медиаплееры не считаются уведомлениями** — музыка, голосовые и видео не
  вызывают срабатываний.

### Звонки

- **Чёрный или белый список** номеров.
- **Международные форматы**: `+375 29 …`, `8 900 …`, `+998 …` — сравнение по
  значащим цифрам, а не по строке.
- **Шаблоны** вида `+7900*` и короткие подстроки вида `8800`.
- Правило «Пропускать» **всегда сильнее** правила «Блокировать».
- Заблокированный вызов отклоняется молча.

### Архив и обучение

- **Локальный архив** всех уведомлений и звонков с поиском и фильтрами.
- **Ручная разметка** записей — она же обучающая выборка.
- **Наивный Байес на устройстве**: ключевой признак — приложение, плюс слова
  заголовка и текста. Обучение мгновенное, порог уверенности настраивается.
- **Объяснимость**: у каждой записи видно, какое правило сработало
  («Правило приложения», «ML (80%)», «По умолчанию»).

### Режимы и звук

- **Быстрые режимы прямо в шторке**: обычный · вибро · тихий.
- **Ночной режим по расписанию** с ручным приоритетом до конца ночного окна.
- **Свои мелодии** для звонков и уведомлений, отдельные громкости.
- **Объединение звуков**: пачка уведомлений даёт один сигнал, а не какофонию.
- **Корректный аудиофокус**: чужая музыка приглушается и возвращается обратно.

### Приватность

- **Никакой сети** — данные не покидают устройство.
- **Опциональное шифрование архива** (SQLCipher, ключ в аппаратном Keystore).
- **Опциональный вход по биометрии или пину**, с защитой от съёмки экрана.
- **Облачный бэкап запрещён** на уровне манифеста.
- **Экспорт и импорт** правил и обучающей выборки в JSON.

## Как это работает

Android не позволяет стороннему приложению отменить звук чужого уведомления:
звук проигрывает система в момент публикации, **раньше** чем слушатель успевает
среагировать. Обойти это без root невозможно.

Поэтому Trinotify использует честный компромисс:

1. Включается системный режим **«Не беспокоить»** с политикой, при которой
   уведомления видны, но беззвучны.
2. Все чужие уведомления таким образом замолкают.
3. То, что прошло ваши правила, **Trinotify озвучивает сам** — собственным
   проигрывателем через поток будильника.

Побочный эффект — постоянная иконка «Не беспокоить» в статус-баре. Убрать её
нельзя: системные индикаторы рисует SystemUI, стороннего API для них не
существует.

Подробный разбор архитектуры, включая обход особенностей MIUI, устройство
классификатора и модель угроз: **[ARCHITECTURE.md](ARCHITECTURE.md)**.

## Установка

### Готовый APK

1. Скачайте APK со страницы [Releases](../../releases).
2. Разрешите установку из неизвестных источников.
3. Установите и откройте приложение.

### Выдача разрешений

Откройте **Настройки → Разрешения** внутри приложения — там показан статус
каждого доступа и кнопка выдачи:

| Разрешение | Зачем нужно |
|---|---|
| Доступ к уведомлениям | чтение и удаление уведомлений — основа работы |
| Управление «Не беспокоить» | системное глушение чужих звуков |
| Роль «Определитель номера» | фильтрация входящих звонков |
| Состояние телефона | собственный рингтон при входящем вызове |
| Батарея без ограничений | чтобы система не выгружала сервис |

**Владельцам Xiaomi/MIUI:** дополнительно включите **«Автозапуск»** для
Trinotify в системных настройках приложений — иначе оболочка будет выгружать
фоновый сервис.

### Первая настройка

1. Включите **«Режим тишины»** (Настройки → Основное) — это включит системное
   «Не беспокоить».
2. Выберите **«Действие по умолчанию»**: что делать с приложениями без правил.
3. На вкладке **«Приложения»** назначьте правила важным приложениям.
4. Через несколько часов работы откройте **«Архив»**, разметьте десяток
   записей и нажмите **«Переобучить модель»**, если хотите использовать ML.

## Сборка из исходников

### Что понадобится

- JDK 17
- Android SDK (compileSdk 34, build-tools 34+)
- Gradle 8.7+ (или Android Studio)

### Шаги

```bash
git clone <адрес-репозитория>
cd Trinotify

# Путь к вашему Android SDK
echo "sdk.dir=/путь/к/Android/Sdk" > local.properties

# Отладочная сборка
gradle assembleDebug

# Юнит-тесты (24 теста)
gradle testDebugUnitTest
```

Готовый APK окажется в `app/build/outputs/apk/debug/`.

### Подписанная релизная сборка

```bash
# Создайте своё хранилище ключей
keytool -genkeypair -v -keystore trinotify.keystore -alias trinotify \
        -keyalg RSA -keysize 2048 -validity 10000

# Пропишите пароли
cp keystore.properties.example keystore.properties
# затем отредактируйте keystore.properties

gradle assembleRelease
```

Файлы `keystore.properties`, `*.keystore` и `local.properties` внесены в
`.gitignore` и **никогда не должны попадать в репозиторий**. Если файла подписи
нет, сборка всё равно пройдёт — APK просто останется неподписанным.

## Приватность

Приложение по своей природе видит очень чувствительные данные: переписку, коды
подтверждения, номера звонящих. Поэтому:

- **нет ни одного сетевого вызова** — ни аналитики, ни телеметрии;
- архив **исключён из облачного бэкапа** (`allowBackup="false"` и явные правила
  извлечения данных);
- шифрование базы — **опция**: SQLCipher, ключ в аппаратном Android Keystore,
  неизвлекаемый даже при доступе к файлам;
- вход в интерфейс можно закрыть **биометрией или пином**, при этом окно
  помечается `FLAG_SECURE` (нет превью в «Недавних» и скриншотов);
- экспортируемый JSON **не шифруется** — он содержит тексты уведомлений,
  храните его осознанно.

Известное ограничение: при включённом шифровании после перезагрузки телефона и
до первой разблокировки экрана база недоступна — в это окно фильтрация работает
по действию по умолчанию, без записи в архив.

## Ограничения

Честный список того, чего приложение не может:

- **Иконки статус-бара** (луна «Не беспокоить») убрать невозможно — это система.
- **Звонки от контактов** Android не передаёт в фильтр, они проходят всегда.
- **Экстренные вызовы** не фильтруются — и не должны.
- **Правило отправителя без указания приложения** может сработать на чужое
  уведомление с таким же заголовком; интерфейс об этом предупреждает.
- Уведомление блокируется **после** появления, а не до — иначе на Android
  нельзя.

# ЕСЛИ У ВАС ЧТО-ТО НЕ РАБОАТЕТ

Пришло много репортов, спасибо всем. Отвечаю сразу всем разом, потому что вопрос по сути один.

Короткий ответ

Trinotify написан и отлажен на одном телефоне с одной прошивкой. Там он работает как задумано. А дальше начинается Android.

Почему так

Android это не одна операционная система. Это база от Google, поверх которой каждый производитель кладёт свою оболочку и свои правила игры. И Trinotify по своей природе живёт ровно в тех местах системы, куда производители лезут чаще всего.

Фон. Приложение обязано слушать уведомления круглосуточно. А оболочки, наоборот, натренированы выгружать всё лишнее ради батареи. Отсюда жалоба «на одном телефоне звук есть при выключенном экране, на другом только после разблокировки». Код тот же самый, поведение системы разное.

Права. Роль «Определитель номера» это системный механизм. Производитель может её не отдать, перехватить своим диалером или выдать вместо неё ошибку. Приложение честно просит, система честно отказывает.

Звук. Trinotify намеренно проигрывает свои сигналы через поток будильника, потому что это единственный поток, который не глушится системным «Не беспокоить», а без «Не беспокоить» вся схема не работает. Побочный эффект в том, что на части устройств поток будильника принципиально не уходит в Bluetooth наушники, чтобы человек не проспал. Это не поломка, это следствие архитектуры. 

Если приложение замолкает при выключенном экране, сначала снимите с него все ограничения энергосбережения в настройках батареи, а на оболочках Xiaomi, realme, OPPO, vivo и Huawei дополнительно включите автозапуск.

Чинить все под каждую модель смартфона у меня не выйдет, так как одно дело погонять Trinotify на эмуляторе, другое на живом устройстве. Купить 20 смартфонов для теста, то такое. Сам продолжаю пользоваться им на Redmi Note 10 Pro, под него приложение и писалось, проблем с ним никаких.
